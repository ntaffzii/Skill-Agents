# คู่มือสกิลใหม่ (ฉบับเข้าใจง่าย)

อธิบาย 2 สกิลที่เพิ่งสร้าง — ไม่มีศัพท์เทคนิคเยอะ อ่านจบแล้วรู้เลยว่าใช้ตอนไหน

---

## 1. `backtest-expert` — "ถ้ากลยุทธ์นี้ใช้เมื่อก่อน จะได้กำไรจริงไหม"

### ปัญหาที่มันแก้

สมมุติคุณคิดกฎเทรดขึ้นมา 1 ข้อ เช่น "ซื้อตอนราคาขึ้นเหนือเส้นค่าเฉลี่ย ขายตอนราคาลงต่ำกว่าเส้นค่าเฉลี่ย" — ก่อนจะเอาเงินจริงไปเสี่ยงกับกฎนี้ อยากรู้ก่อนว่า **ถ้าใช้กฎนี้กับข้อมูลราคาย้อนหลัง จะได้กำไรหรือขาดทุน**

`backtest-expert` ทำหน้าที่นี้ — เอากฎ + ราคาย้อนหลังมาจำลองดูว่าถ้าเทรดตามกฎนี้จริงๆ ผลจะเป็นยังไง

### ใช้ตอนไหน

- มีไอเดียกฎเทรด อยากรู้ว่าใช้ได้จริงไหมก่อนลงเงินจริง
- อยากเทียบกฎ 2-3 แบบว่าแบบไหนดีกว่ากัน จากข้อมูลราคาชุดเดียวกัน

### ได้อะไรกลับมา

| คำตอบที่ได้ | หมายถึง |
|---|---|
| Win rate | เทรด 10 ครั้ง กำไรกี่ครั้ง |
| กำไรเฉลี่ยต่อครั้ง | โดยเฉลี่ยแต่ละไม้ได้/เสียกี่ % |
| Max drawdown | ตอนที่แย่ที่สุด พอร์ตลดลงไปกี่ % จากจุดสูงสุด (**สำคัญ** — เป็นตัวเลขที่บอกว่าเสี่ยงแค่ไหนกว่าจะได้กำไรตามนั้น) |
| Profit factor | กำไรรวมทั้งหมด หารด้วย ขาดทุนรวมทั้งหมด — มากกว่า 1 แปลว่ากำไรมากกว่าขาดทุน |

### ⚠️ สิ่งที่ต้องระวัง (สำคัญมาก)

1. **ไม่ใช่คำแนะนำการลงทุน** — บอกแค่ว่า "ในอดีตแบบนี้" ไม่ได้การันตีอนาคต
2. **ระวังการปรับจนพอดี (overfitting)** — ถ้าลองปรับค่าไปเรื่อยๆ จนได้ตัวเลขที่ชอบ จากข้อมูลชุดเดียวกันที่ใช้ทดสอบ ตัวเลขนั้นจะดูดีเกินจริง ต้องเอาไปลองกับข้อมูลชุดใหม่ที่ไม่เคยใช้ตอนปรับด้วย
3. **ไม่รวมค่าคอม/สเปรด** — กำไรจริงจะน้อยกว่าที่ backtest บอกเสมอ

### 🐛 บั๊กที่เจอตอนตรวจสอบ (แก้แล้ว)

ตอนแรกเขียนโค้ดผิด — เช็ค "พอร์ตลดลงมากสุดกี่ %" (max drawdown) แค่ตอน**ปิดไม้**เท่านั้น ไม่ได้เช็คระหว่างที่ยังถือไม้อยู่

ตัวอย่างที่พิสูจน์ว่าผิดจริง: ซื้อที่ 100 บาท ราคาร่วงลงไป 50 บาทระหว่างถือ (ขาดทุน 50% ชั่วขณะ) แล้วค่อยฟื้นขึ้นมาขายที่ 110 บาท (กำไร 10%) — โค้ดเดิมจะบอกว่า **max drawdown = 0%** ทั้งที่จริงพอร์ตเคยลดลงไปตั้ง 50% ระหว่างทาง! แก้แล้วให้เช็คทุกวันที่ถือไม้อยู่ ไม่ใช่แค่วันปิดไม้

## 2. `research-methodology` — "ค้นให้ครบก่อนสรุป ไม่ใช่เจออันแรกแล้วจบ"

### ปัญหาที่มันแก้

เวลาค้นข้อมูล (เช่นหาข่าว, เทียบ repo, สำรวจโปรเจกต์) เรามักจะ**หยุดค้นทันทีที่เจออะไรที่ฟังดูสมเหตุสมผล** — ปัญหาคือ:
- อาจจะไม่ใช่แหล่งข้อมูลที่ดีที่สุด (แค่หาเจอก่อน)
- "3 เว็บบอกเหมือนกัน" อาจจะแค่ก็อปกันมาจากที่เดียว ไม่ใช่ยืนยันจริง 3 ที่

### ใช้ตอนไหน

เป็น**ขั้นตอนก่อนเริ่มค้น** ใช้คู่กับสกิลค้นข้อมูลที่มีอยู่แล้ว:
- ก่อนใช้ `daily-news-report` (ทำข่าวประจำวัน)
- ก่อนใช้ `github-skill-research` (เทียบ repo สกิลต่างๆ)
- ก่อนใช้ `project-discovery` (สำรวจโปรเจกต์)

### หลักการง่ายๆ 3 ข้อ

1. **ตั้งคำถามให้ชัดก่อนค้น** — "เล่าเรื่อง X ให้หน่อย" (กว้างไป) → "เอกสารทางการของ X บอกค่า default ไว้เท่าไหร่" (ชัดเจน ค้นตรงจุด)
2. **แบ่งชั้นความน่าเชื่อถือของแหล่งข้อมูล** — เอกสารทางการ/source code ตัวจริง > บล็อกคนดูแลโปรเจกต์ > บล็อกทั่วไป/ฟอรั่ม
3. **จดไว้ว่าเช็คอะไรไปแล้ว อะไรยังไม่ได้เช็ค** — กันไม่ให้สรุปโดยดูเหมือนครบ ทั้งที่จริงเช็คไปแค่ 3 จาก 10 ผลลัพธ์

### เกี่ยวกับ `claim-citation-check` ยังไง

คนละจังหวะกัน — `research-methodology` ใช้**ก่อนค้น** (วิธีค้นให้ครบ), `claim-citation-check` ใช้**หลังเขียนเสร็จ** (เช็คว่าที่เขียนมีแหล่งอ้างอิงจริงไหม) ใช้คู่กันได้ ไม่ทับซ้อนกัน

---

## สรุปสั้นๆ

| สกิล | ตอบคำถามว่า | ใช้ตอนไหน |
|---|---|---|
| `backtest-expert` | กลยุทธ์นี้เคยได้ผลไหม | ก่อนเทรดด้วยเงินจริง |
| `research-methodology` | ค้นครบหรือยัง | ก่อนเริ่มค้นข้อมูลสำหรับ research skill ไหนก็ได้ |

ทั้งสองตัวผ่านการตรวจสอบด้วย `/code-review` แล้ว — `backtest-expert` เจอบั๊กจริง 1 ตัว (max drawdown คำนวณผิด) แก้และเทสต์ซ้ำแล้ว ส่วน `research-methodology` เป็นสกิลเชิงเนื้อหา (ไม่มีโค้ด) ตรวจสอบเนื้อหาแล้วไม่พบปัญหา
