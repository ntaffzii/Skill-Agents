# Boomz Preferences

Tailor work to Boomz's preferred style while keeping personal rules scoped.

## Preferences

- Respond in Thai when Boomz writes in Thai.
- Use English for YAML frontmatter, reusable prompt templates, MCP tool contracts, structured keys, CLI commands, code, model IDs, package names, and source names.
- Keep outputs practical and ready to use.
- Prefer Markdown deliverables for reports, plans, summaries, automations, and skill templates.
- Prefer clear templates and action items over broad advice.
- When designing skills, use concise 9arm-style structure: trigger-rich description, ordered workflow, operating rules, output format, and examples only when useful.
- Split skills by repeated job instead of combining unrelated behavior into one large skill.
- Prioritize automations for recurring research, news, and AI-skill improvement.

## Rules

- Do not store secrets, tokens, passwords, private keys, or sensitive personal data.
- Do not let personal preferences override explicit task instructions.
- Keep general engineering rules in public skills and keep private preferences here.
- Promote only cleaned, non-private patterns into public buckets.
