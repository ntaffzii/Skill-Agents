# Consent Banner — Template (PDPA-aware)

> Synthetic example. ไม่ใช่คำแนะนำทางกฎหมาย — ให้ที่ปรึกษากฎหมาย/DPO ตรวจสอบก่อนใช้จริง.

## สิ่งที่ต้องมี (PDPA requirements a banner must satisfy)

- Checkbox ต้อง **ไม่ติ๊กไว้ล่วงหน้า** (no pre-checked box) — ผู้ใช้ต้องกดยินยอมเอง
- แยกความยินยอมสำหรับแต่ละวัตถุประสงค์ที่ไม่ใช่สิ่งจำเป็นต่อการให้บริการ (granular consent) — อย่ารวมทุกอย่างไว้ใน checkbox เดียว
- ต้องมีทางเลือก "ปฏิเสธ" ที่เด่นชัดเท่ากับ "ยอมรับ" — ห้ามออกแบบให้ปุ่มปฏิเสธหาไม่เจอหรือเล็กกว่าปุ่มยอมรับ (dark pattern)
- ภาษาที่ใช้ต้องเข้าใจง่าย ไม่ใช้ภาษากฎหมายที่อ่านยากเพื่อกลบเกลื่อนเนื้อหา
- ต้องมีลิงก์ไปยังนโยบายความเป็นส่วนตัวฉบับเต็ม
- คุกกี้ที่จำเป็นต่อการทำงานของเว็บไซต์ (strictly necessary) ไม่ต้องขอความยินยอม แต่ต้องแจ้งให้ทราบว่ามีการใช้งาน

## ตัวอย่าง (Example)

```
เว็บไซต์นี้ใช้คุกกี้เพื่อ:
[ ] คุกกี้ที่จำเป็น (เปิดใช้งานเสมอ ไม่สามารถปิดได้)
[ ] คุกกี้เพื่อการวิเคราะห์การใช้งาน (ไม่ติ๊กไว้ล่วงหน้า)
[ ] คุกกี้เพื่อการตลาด/โฆษณา (ไม่ติ๊กไว้ล่วงหน้า)

[ยอมรับทั้งหมด]   [ปฏิเสธที่ไม่จำเป็น]   [ตั้งค่า]

อ่านเพิ่มเติมได้ที่ [นโยบายความเป็นส่วนตัว]
```

## สิ่งที่ห้ามทำ (anti-patterns to avoid)

1. ติ๊ก checkbox ไว้ล่วงหน้าให้ผู้ใช้ — ขัด PDPA โดยตรง
2. รวมความยินยอมคุกกี้การตลาดเข้ากับข้อกำหนดการใช้งานทั่วไปแบบ all-or-nothing
3. ทำให้ปุ่ม "ปฏิเสธ" หายาก จาง หรือคลิกยาก เมื่อเทียบกับปุ่ม "ยอมรับ"
4. ไม่มีช่องทางถอนความยินยอมภายหลัง หรือถอนได้ยากกว่าตอนให้ความยินยอม

---

*Template นี้อิงหลักการทั่วไปของ PDPA เรื่อง valid consent (freely given, specific, informed, unambiguous, no pre-ticked box) ไม่ใช่คำแนะนำทางกฎหมาย.*
